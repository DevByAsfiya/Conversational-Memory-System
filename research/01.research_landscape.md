# Research Landscape: Conversational Memory System

**Last updated:** 5th August 2026
**Domain:** Coding / debugging assistant

## How to read this

This is a standing map of research across every system component. It is updated each week as new sources are found.

- **Baseline:** sources named in the handbook reference list.
- **Additional:** sources found during the weekly scans.
- **Coverage:** my own honest assessment of how well I currently understand a component well enough to design it: `strong`, `partial`, or `gap`.
- **Open gap:** the specific unresolved question inside that component.

---

## 1. Memory model and representation

- **Maps to:** R1 (what to store), R3 (separate reported from believed)
- **Coverage:** partial
- **Baseline:** Memory Networks [3], End-to-End Memory Networks [2], Neural Turing Machines [1] (historical)
- **Additional found:** none yet
- **Open gap:** whether memory should be structured records or free text for a coding domain

## 2. Attention and context

- **Maps to:** R9 (bounded budget)
- **Coverage:** strong
- **Baseline:** Attention Is All You Need [4]
- **Additional found:** none yet
- **Open gap:** none pressing, covered by baseline plus MemGPT

## 3. Memory extraction and admission

- **Maps to:** R1 (what to store), R2 (provenance), R17 (admission control)
- **Coverage:** gap
- **Baseline:** none named in the handbook
- **Additional found:** to fill in scan
- **Open gap:** what deserves storage, how to score salience, how to block sensitive data at intake

## 4. Retrieval augmentation

- **Maps to:** R7 (iterative retrieval), R8 (detect incomplete retrieval)
- **Coverage:** partial
- **Baseline:** RAG [5], RETRO [6], Memorizing Transformers [7]
- **Additional found:** none yet
- **Open gap:** iterative or active retrieval, and how to know when enough has been retrieved

## 5. Index and storage layer

- **Maps to:** R4 (deletion), R16 (per-user isolation)
- **Coverage:** partial
- **Baseline:** FAISS [10], HNSW [11]
- **Additional found:** none yet
- **Open gap:** filtering retrieval by tenant, and whether deletion from a vector index is reliable

## 6. Ranking and conflict resolution

- **Maps to:** R5 (supersession), R6 (rank on more than similarity), R12 (corrections stick)
- **Coverage:** partial
- **Baseline:** Generative Agents [8]
- **Additional found:** none yet
- **Open gap:** temporal validity, handling contradictions, deciding which of two records is current

## 7. Context construction

- **Maps to:** R9 (bounded budget), R18 (injection defence)
- **Coverage:** partial
- **Baseline:** MemGPT [9], RAG [5]
- **Additional found:** none yet
- **Open gap:** protecting the context against prompt injection carried in stored memory

## 8. Reflection and lifecycle

- **Maps to:** R5 (retire stale facts), R13 (consolidate)
- **Coverage:** partial
- **Baseline:** Generative Agents [8], MemGPT [9]
- **Additional found:** none yet
- **Open gap:** decay and expiration, and applying corrections without reinforcing earlier errors

## 9. Evaluation and observability

- **Maps to:** all requirements, and needed before Deliverable 3
- **Coverage:** gap
- **Baseline:** none named (the MemGPT Deep Memory Retrieval task and the MSC dataset are starting points)
- **Additional found:** to fill in scan
- **Open gap:** component-level metrics, failure taxonomies, and a regression dataset

## 10. Privacy, safety, and isolation

- **Maps to:** R16 (isolation), R17 (admission), R18 (integrity)
- **Coverage:** gap
- **Baseline:** none named in the handbook
- **Additional found:** to fill in scan
- **Open gap:** PII admission rules, cross-tenant leakage, deletion guarantees, and memory poisoning

## Sources glimpsed

**Machine unlearning for LLMs (survey).** Zhang et al., A Comprehensive Survey of LLM
Unlearning, 2025. https://arxiv.org/abs/2503.01854
Mechanism offered: techniques to remove the influence of specific training data from a
model's weights without full retraining (gradient ascent on a forget set, fine-tuning
toward a refusal state, preference-based methods).
Relevance: addresses the "right to be forgotten" (GDPR, EU AI Act), which maps to my
deletion requirement R4. Needs examination for whether it applies to my architecture.

**When Machine Unlearning Meets RAG.** (Noted from search; to glance at.)
Relevance: closest work to my case, since it concerns external retrieval memory rather
than pure model weights. Worth a short check to confirm it does not change the deletion
conclusion.

**FAISS: Billion-scale Similarity Search with GPUs.** Johnson, Douze, Jegou, 2017.
https://arxiv.org/abs/1702.08734
Mechanism offered: the IVFADC index partitions vectors into inverted lists via a coarse
quantizer, and a query scans only a selected subset of lists rather than the whole
database (§2).
Relevance: shows that restricting a search to a subset is structural to the index, which
is the basis for filtering. But the partitioning is by geometric similarity, not by owner,
so it does not itself provide isolation.

**HNSW: Efficient and Robust ANN Search using Hierarchical NSW Graphs.** Malkov, Yashunin, 2018.
https://arxiv.org/abs/1603.09320
Mechanism offered: a graph-based index where nodes are linked to nearby nodes; search
walks the graph from a shared top-layer entry point (§4). Per-element link overhead is
about 60 to 450 bytes (§4.2.3).
Relevance: relevant to both isolation and deletion. The graph deliberately links
semantically similar nodes, and lists element removal as unsupported (§6), which bears
directly on R16 and R4.

## Mechanisms found and first-pass relevance

**Unlearning (removal from weights).** The survey's own motivation makes clear that
unlearning exists because problematic data becomes absorbed into model parameters during
training, where it cannot be simply deleted and full retraining is prohibitively costly.
First-pass judgment: likely NOT applicable, because my memory is stored externally, not
in the model's weights. Flagged for full evaluation and a probable reject.

**Subset-restricted search (FAISS IVF).** The index natively scans only part of the
database per query, so filtering a search to a subset is architecturally normal. However,
FAISS groups vectors by similarity, so two users' similar memories land in the same
inverted list. Isolation therefore cannot rely on the index's own partitioning; it needs
a separate filter by owner. First-pass judgment: relevant, carry to evaluation.

**Graph-index deletion difficulty (HNSW).** Insertion modifies neighbouring nodes' links
and prunes full nodes (§4), so every node participates in routing paths for others.
Removing a node can strand other nodes and degrade recall, which is why the paper lists
removal as future work (§6). First-pass judgment: relevant to R4, gives deletion an honest
caveat. Carry to evaluation.
